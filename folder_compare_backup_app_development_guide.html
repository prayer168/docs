1. 專案概述

本專案要建立一套 Windows 桌面 App，使用者只要指定兩個資料夾，就能先取得完整差異清單，再依照每個檔案的狀態，選擇是否更新，以及由哪一邊更新到另一邊。

產品核心原則：比對與更新必須分成兩個階段。第一次按下「開始比對」時，系統只能讀取資料，不能新增、覆蓋、改名或刪除任何檔案。

主要使用情境

教材與外接硬碟

比較教師電腦中的教材與外接硬碟備份，找出新增或更新的檔案。

網站與程式專案

比較本機專案、備份目錄或另一台電腦複製下來的版本。

照片與研究資料

比對大量照片、影片、科展記錄、實驗數據與研究文件。

核心功能

  • 選擇資料夾 A 與資料夾 B。
  • 遞迴掃描所有子資料夾。
  • 依相對路徑、檔案大小、修改時間與 SHA-256 比較。
  • 顯示 A 較新、B 較新、只有 A、只有 B、完全相同與衝突。
  • 逐項或批次選擇更新方向。
  • 更新前產生預覽。
  • 覆蓋前保留舊版本。
  • 複製後重新驗證。
  • 產生 HTML、CSV 或 JSON 報告。

2. MVP：最小可行產品

MVP 是 Minimum Viable Product，中文通常翻譯為「最小可行產品」。它不是粗糙的半成品，而是以最少但完整的功能，先建立一個可以真正使用、測試與驗證需求的第一版。

對本專案而言，MVP 的目標不是立即加入 AI 文件分析、雲端、NAS、排程、鏡像刪除與多語言；而是先把「比較、選擇、預覽、安全更新、驗證」做正確。

MVP 必備功能

功能是否列入 MVP理由
選擇兩個資料夾是整個工作流程的入口。
日期與大小快速比對是可快速處理大量檔案。
SHA-256 精確比對是，先針對可疑檔案避免只靠時間戳記誤判。
逐項選擇更新方向是確保使用者掌握決策。
更新前預覽是降低誤覆蓋風險。
歷史版本是覆蓋錯誤時可以復原。
預設刪除或鏡像否風險過高，不適合第一版。
AI 文件差異摘要否屬進階功能，核心 App 不應依賴 AI。

MVP 與原型的差別

只有畫面、按鈕無法真正讀取資料夾，屬於 UI 原型；能夠實際掃描、產生差異、安全更新與產生紀錄，才是可用的 MVP。

6. 系統操作流程

選擇資料夾
唯讀掃描
產生差異
人工選擇
安全更新

完整流程

  1. 使用者指定資料夾 A 與資料夾 B。
  2. 系統檢查兩個路徑不能相同或互為子資料夾。
  3. 遞迴掃描兩邊檔案，建立相對路徑索引。
  4. 先以修改時間與檔案大小快速比較。
  5. 對可疑檔案計算 SHA-256。
  6. 將結果分類並顯示摘要。
  7. 使用者逐項或批次選擇操作。
  8. 系統顯示更新預覽、檔案數量與總容量。
  9. 覆蓋前將舊檔放入歷史版本。
  10. 將來源檔寫入暫存檔，驗證後再取代正式檔案。
  11. 產生結果與錯誤報告。

7. 檔案比對邏輯

以相對路徑作為比對鍵

資料夾 A：D:\教材\自然\植物\葉片.docx
資料夾 B：E:\備份\自然\植物\葉片.docx

共同比對鍵：自然\植物\葉片.docx

狀態分類

狀態判斷方式預設建議
identical大小與時間相同，或 SHA-256 相同不處理
only_in_a只有資料夾 A 有檔案A → B
only_in_b只有資料夾 B 有檔案B → A
a_newerA 修改時間較晚A → B
b_newerB 修改時間較晚B → A
same_time_different_size時間相同但大小不同暫停，精確比對
same_size_different_content大小相同但 SHA-256 不同人工判斷
conflict兩邊自上次同步後都修改不得自動處理
unreadable權限、鎖定或其他錯誤略過並記錄

時間容許差

FAT、NTFS、外接硬碟與雲端同步資料夾的時間精度可能不同，因此應提供 timestampToleranceSeconds，例如預設 2 秒。時間差在容許範圍內時，再比較大小或雜湊。

SHA-256 精確比對

雜湊應採串流方式讀取，不可將大型影片整個載入記憶體。第一版可先對時間或大小有疑問的項目計算，避免所有檔案都計算而拖慢掃描。

8. 安全同步設計

檔案同步最大的風險不是「比對不準」，而是錯誤覆蓋、批次誤刪、來源在比對後發生變化，或複製中斷造成目的檔損壞。因此同步引擎必須採用防破壞設計。

安全更新六步驟

  1. 重新確認來源檔案仍存在，且 metadata 未改變。
  2. 檢查目的磁碟空間與寫入權限。
  3. 將目的端舊檔備份到歷史版本資料夾。
  4. 把來源檔複製到目的端暫存檔。
  5. 比較來源與暫存檔的大小及 SHA-256。
  6. 驗證成功後，才用暫存檔取代正式目的檔。
來源：report.docx
暫存：report.docx.fcb-temp-550e8400
舊版：.history/2026-07-28_193000/report.docx
正式：report.docx

保留雙版本

科展計畫書__from-A__2026-07-28_193000.docx
科展計畫書__from-B__2026-07-28_193000.docx

取消操作

使用者取消時，已完成項目保留；正在複製的暫存檔應清除；未開始項目標記為取消；不可刪除原有目的檔。

SQLite 建議資料表

至少建立 folder_pairs、compare_jobs、diff_entries、sync_jobs、sync_items 與 snapshots。

CREATE TABLE folder_pairs (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  folder_a TEXT NOT NULL,
  folder_b TEXT NOT NULL,
  settings_json TEXT NOT NULL,
  created_at TEXT NOT NULL,

Snapshot 可用於第二版雙向同步：記錄上次同步時 A、B 兩邊的雜湊與修改時間，才能判斷是否為真正的雙方修改衝突。

主畫面四大區域

比對結果

更新與報告

批次選擇、更新預覽、進度、取消、歷史版本與匯出。

結果表格建議欄位

勾選、狀態、相對路徑、檔名、A 大小、B 大小、A 修改時間、B 修改時間、雜湊結果、建議動作、選擇動作與風險等級。

批次操作

全部使用較新版本全部 A → B全部 B → A只處理新增檔案衝突全部略過清除全部選擇

批次操作不得直接套用到高風險衝突；顏色必須搭配圖示與文字，不能只依賴顏色傳達狀態。

11. 安全規則

  • 比對階段永遠唯讀。
  • 第一版預設不提供刪除。
  • 衝突項目預設動作必須是「不處理」。
  • A、B 相同或互為子資料夾時阻擋執行。
  • 歷史版本目錄不得位於同步掃描範圍內。
  • 來源在比對後若改變，該項目必須重新比對。
  • 大量覆蓋或異常變更必須額外警告。
  • 錯誤不可靜默忽略。
  • Renderer 不可直接取得 Node.js 或完整檔案系統權限。
  • 不得把使用者檔案內容上傳至外部 AI 服務。

大量異常保護

  • 超過 1,000 個檔案將被更新。
  • 超過 20% 檔案將被覆蓋。
  • 超過 10 GB 資料將被複製。
  • 大量檔案突然變成 0 bytes。
  • 來源或目的磁碟代號與上次不同。

12. 測試策略

單元測試

測試相對路徑、時間容許差、大小比較、雜湊比較、狀態分類、排除規則、歷史版本路徑與錯誤轉換。

整合測試情境

一般情境

  • 完全相同
  • 只有 A／只有 B
  • A 較新／B 較新
  • 相同大小但內容不同
  • 空資料夾與 Unicode 中文檔名

異常情境

  • 權限不足
  • 檔案被鎖定
  • 磁碟空間不足
  • 複製中斷與使用者取消
  • SHA-256 驗證失敗

效能測試

應至少測試 1,000、10,000 與 100,000 個檔案。結果表格必須採虛擬化顯示；雜湊與複製採串流；並限制 hash 與 copy 的同時工作數。

13. AI Agent 開發流程

AI Agent 可以負責規劃、寫程式、執行測試、修正錯誤與產生文件，但不應自行決定高風險同步操作。

建議先建立的專案文件

AGENTS.md

說明安全規則、工具限制與開發慣例。

ARCHITECTURE.md

說明前後端模組、IPC、資料流與同步核心。

PLAN／TASKS.md

把開發階段拆成可執行、可測試的小任務。

分階段開發順序

  1. 初始化 Electron 或 Tauri 專案。
  2. 完成資料夾選擇與唯讀掃描。
  3. 完成快速比對與結果表格。
  4. 加入 SHA-256 精確比對。
  5. 加入逐項與批次操作。
  6. 完成更新預覽。
  7. 完成歷史版本與暫存檔安全複製。
  8. 完成更新後驗證、取消與錯誤處理。
  9. 加入 SQLite、歷史紀錄與報告。
  10. 打包 Windows 安裝檔。
每一階段完成後，AI Agent 都應回報：完成項目、修改檔案、測試方法、測試結果、已知限制與下一步。不可一次寫完整專案卻從未啟動或測試。

16. 驗收標準

功能驗收

  • 可選擇兩個資料夾並掃描子資料夾。
  • 可正確分類相同、單邊存在、A 較新、B 較新與衝突。
  • 可對可疑檔案執行 SHA-256。
  • 可逐項與批次選擇更新方向。
  • 執行前有完整預覽。
  • 覆蓋前有歷史版本。
  • 複製後有大小與 SHA-256 驗證。
  • 可取消掃描與同步。
  • 可輸出 HTML、CSV、JSON 報告。

安全驗收

  • 比對階段不修改任何檔案。
  • 預設沒有刪除行為。
  • 衝突不自動覆蓋。
  • 來源變動會要求重新比對。
  • 複製或驗證失敗不破壞正式目的檔。
  • 所有錯誤都有結構化紀錄。
當 App 能夠在 Windows 11 真實安裝、選擇兩個資料夾、正確比對、安全更新、通過測試並提供完整文件時，才可以視為第一版完成。
