AI 專案知識工作流

把教學靈感、科展研究、AI 生成、數位教材與程式開發，轉化為可追蹤、可查證、可備份、可發布、可再次利用的長期知識資產。

Obsidian 知識核心 Notion／Linear 任務 Drive 成果檔案 GitHub 程式版本 Science Portal 發布

Abstract

這不是多裝一套工具，而是建立一個專案作業系統

這套工作流源自一個很實際的需求：AI 可以迅速產生教案、科展建議、圖片、簡報、文件與程式，但若每次生成後只留在對話裡，成果會逐漸失去版本、來源、脈絡與後續價值。因此，系統的目標不是把資料全部塞進同一個平台，而是替每種資料指定唯一正式位置，並用統一編號、欄位、檔名、版本、證據與隱私規則把它們串起來。

01 · Problem framing

從零散成果走向可重用知識

成果四散

提示詞留在對話、檔案留在 Drive、程式在 GitHub、想法在 Obsidian，彼此缺乏索引。

版本失控

常出現 final、最新版、最終版2，無法確定哪一份才是正式成果。

來源斷裂

報告、簡報與網站引用不同版本數據，結論無法回溯至原始證據。

AI 假完整

文字看似完美，但可能把推論當事實、補造數據或掩蓋研究限制。

隱私風險

學生姓名、照片、成績、帳密或同意書可能誤入公開知識庫與 GitHub。

專案結束即失憶

沒有回顧、錯誤紀錄與可重用模組，下一次仍然從零開始。

設計目標

  1. 讓任何長期工作都能從原始想法建立正式 Project ID。
  2. 讓不同平台各自保存最適合的內容，並以連結與欄位互相對應。
  3. 讓 AI 讀得懂專案結構，也知道不能越過的隱私、證據與發布界線。
  4. 讓每個成果都有可驗證的來源、版本、位置與人類審查紀錄。
  5. 讓結案後的提示詞、模板、程式與錯誤經驗可以再次使用。

04 · Workflow

九階段與九道品質閘門

Stage 0｜初始化 → G0

決定模式、專案編號、任務平台、隱私、AI 權限、正式位置與下一步。

Stage 1｜收件

保存原始想法，分離已知事實、現場觀察、假設與待查證問題。

Stage 2｜定義 → G1

建立專案章程、核心問題、範圍、排除範圍、成果與客觀成功條件。

Stage 3｜研究 → G2

建立 Source ID、查核發布日期與適用性，記錄來源能與不能支持的主張。

Stage 4｜設計 → G3

依科展、教材或程式類型定義變因／需求、資料欄位、任務、風險與備案。

Stage 5｜執行

保留原始資料、方法版本、偏差、失敗與決策，只更新唯一任務來源。

Stage 6｜分析 → G4／G5

鎖定 raw、建立 clean／anon，保留修正紀錄，避免把相關寫成因果。

Stage 7｜製作

為報告、簡報、圖片、影片、程式與教材建立 Artifact ID、檔名與版本。

Stage 8｜驗證發布 → G6／G7

執行來源、數據、隱私、跨成果一致性、技術與人工審查。

Stage 9｜封存重用 → G8

完成回顧、備份、未完成任務處理，提取可重用提示詞、模板與程式。

# Manage AI Project Workflow

## Goal

Turn a raw idea or scattered existing work into a traceable project from intake through reuse. Keep one authoritative location per data type, preserve evidence and raw data, and let AI assist without becoming the only store or final decision-maker.

## Choose the operating mode

1. Detect whether the user wants:
   - **Plan only**: propose IDs, metadata, structures, tasks, filenames, and templates without writing files or external systems.
   - **Create locally**: create project files only in the user-approved local destination.
   - **Connect externally**: write to an external platform only when explicitly requested and the relevant tool is available.
   - **Audit**: inventory an existing project without reorganizing or overwriting it.
   - **Review, publish, archive, or retrieve**: run only the relevant stage and its gates.
2. Ask only for missing choices that materially alter the result: title/type, intended outputs, task manager, privacy, and whether writes are authorized.
3. Infer safe defaults when possible and label them. Prefer an existing task manager. Treat Notion and Linear as mutually exclusive authoritative task stores unless the user explicitly requests otherwise.

## Enforce the invariants

- Assign one Project ID and keep it stable.
- Assign IDs to tasks, sources, decisions, experiments, artifacts, and issues when created.
- Keep one authoritative location per information type; link instead of duplicating complete content.
- Separate verified facts, direct observations, inferences, hypotheses, and recommendations.
- Never fabricate sources, URLs, data, observations, experiments, results, files, or external writes.
- State `目前證據不足` when evidence is inadequate.
- Never overwrite raw data, convert missing values to zero, or remove outliers without a documented decision.
- Give every formal artifact a version and compliant filename.
- Give every task an objective acceptance criterion.
- Keep one explicit `next_action`.
- Require human review before public release.
- Treat synchronization as availability, not backup.
- Never expose restricted data or secrets to AI, GitHub, or public portals.

## Route information to its owner

- Use **Obsidian** for project knowledge, sources, decisions, prompts, AI logs, experiment logs, reflections, and retrospectives.
- Use **Notion or Linear** for project/task status, owners, dates, dependencies, and acceptance criteria.
- Use **Google Drive** for office documents, datasets, photos, audio, video, raw records, and release files.
- Use **GitHub** for code, tests, skills, technical documentation, automation, Pages, and releases.
- Use **Science Portal** for verified public entry points and downloads.
- Use **AI** to classify, plan, check, draft, summarize, and retrieve; never use it as the sole store.

Read [platform-ownership.md](references/platform-ownership.md) when assigning locations or auditing duplicates.

## Run the workflow

1. **Intake**: preserve the raw idea and separate what is observed from what is assumed.
2. **Define**: assign the Project ID, create the project charter, scope, outputs, success criteria, privacy, and next action.
3. **Research**: create Source IDs, verify claims, record applicability and limits, and list evidence gaps.
4. **Design**: define experiments, requirements, data fields, tasks, acceptance criteria, risks, and fallback plans.
5. **Execute**: preserve raw records, log deviations, update tasks, and link artifacts.
6. **Analyze**: validate and clean data without mutating raw inputs; separate description from inference.
7. **Create**: produce documents, media, code, teaching materials, and release candidates with traceable versions.
8. **Verify and publish**: check sources, privacy, data, cross-artifact consistency, technical behavior, and permissions before release.
9. **Archive and reuse**: create a retrospective, close or transfer unfinished work, make backups, and extract reusable knowledge.

Read [workflow-stages.md](references/workflow-stages.md) for gates and deliverables. Run only the current stage; do not dump the whole SOP unless the user asks.

## Create IDs and metadata

Use [project-schema.md](references/project-schema.md) to choose the project type, generate IDs, and validate enumerated fields. Keep the same Project ID in Obsidian, task manager, Drive folder, GitHub documentation, artifact names, and portal metadata.

## Name and version artifacts

Use [naming-versioning.md](references/naming-versioning.md). Prefer:

`{PROJECT_ID}__{ARTIFACT_TYPE}__{SLUG}__{STATUS}__v{VERSION}__{YYYYMMDD}.{EXT}`

Never use names such as `final-final`, `最新版`, or `真的最終版`. Preserve raw files and create a new clean or release artifact.

## Protect privacy and evidence

Read [privacy-evidence.md](references/privacy-evidence.md) before handling student data, consent forms, faces, grades, administrative records, credentials, research claims, raw data, or public release. Anonymize before AI processing. Keep restricted material outside the AI-readable public vault.

## Use templates and scripts

- Copy only the needed template from `assets/`; do not fill absent facts with invented values.
- Use `scripts/init_project.py` only after the user authorizes local creation and chooses an explicit output root. Run `--dry-run` first when the target already contains work or scope is uncertain.
- Use `scripts/validate_project.py` to validate a project-home Markdown file or JSON metadata.
- Use `scripts/validate_filename.py` to check one filename or scan a directory.
- Use `scripts/build_artifact_manifest.py` to produce a read-only inventory; do not scan restricted locations without authorization.
- Read [prompt-library.md](references/prompt-library.md) only for the requested stage.

## Handle external systems

- Never claim an external page, repository, folder, release, deployment, or URL exists unless the corresponding tool call succeeded.
- If a connector is unavailable, produce an import-ready template or action list with blank URL fields.
- Before external writes, resolve exact targets, permissions, visibility, and whether the action is within the user's request.
- Do not publish, message, invite, change permissions, or move official data when the user requested only planning or review.

## Audit existing projects

1. Inventory without moving or renaming.
2. Identify authoritative copies, duplicates, stale versions, noncompliant names, missing metadata, sensitive content, and broken links.
3. Propose a reversible migration plan.
4. Ask before material moves, renames, deletions, permission changes, or publication.

## Complete the handoff

End project-workflow responses with:

- Project ID
- Current stage and gate status
- Completed
- Missing or unverified
- Next action
- Recommended authoritative location

# Naming and versioning

## Formal artifact name

`{PROJECT_ID}__{ARTIFACT_TYPE}__{SLUG}__{STATUS}__v{VERSION}__{YYYYMMDD}.{EXT}`

Example: `SF-2026-004__experiment-data__flower-count__clean__v1.0__20261002.csv`

## Rules

- Use ASCII letters, digits, hyphens, double underscores, and one extension separator.
- Use lowercase for artifact type, slug, and status.
- Do not use spaces or Chinese characters in formal cross-platform filenames.
- Put the Chinese title inside the file and metadata.
- Use `YYYYMMDD` in the project timezone.
- Reject `final`, `final2`, `final-final`, `最新版`, `最後版`, and similar labels.
- Use `raw` for immutable original data, `clean` for cleaned data, `anon` for anonymized data, `review` for review candidates, `approved` for approved internal work, `published` for released work, and `archived` for preserved superseded copies.
- Never rename or move existing official files during an audit without approval.

## Versions

| Version | Meaning |
|---|---|
| v0.1 | initial idea |
| v0.2 | defined problem |
| v0.5 | internal pilot |
| v0.9 | release candidate |
| v1.0 | first formal release |
| v1.1 | small correction or addition |
| v1.2 | backward-compatible feature addition |
| v2.0 | major scope, architecture, or research redesign |

Use three-part semantic versions for software releases when patch-level changes matter.

## Folder and branch names

- Project folder: `{PROJECT_ID}_{slug}`
- Repository: lowercase project ID plus slug
- Git branch: `type/short-task-name`
- Commit: imperative change plus task/issue ID

Examples:

`feat/dashboard-filter`

`fix mobile chart overflow SF-2026-004-B003`

## Raw and cleaned data

- Preserve raw bytes and original filename in `04_raw-data`.
- Write transformations to new `clean` or `anon` artifacts.
- Record input file, transformation, operator or script, timestamp, and output file.
- Do not silently correct records.

# Privacy and evidence

## Privacy levels

### Public

- anonymized, verified teaching material
- public code and documentation
- approved research results
- public presentations and downloads

### Internal

- drafts
- working analyses
- teacher discussion
- unverified hypotheses
- non-public project plans

### Restricted

- student names, grades, health, contact information, or identifiable faces
- parent consent forms
- confidential administration
- accounts, passwords, API keys, tokens, or credentials

Never provide restricted material to general AI. Anonymize first and store the identity key outside the AI-readable project. Never publish restricted material to GitHub or Science Portal.

## Evidence labels

- **Verified fact**: supported by an inspected reliable source.
- **Direct observation**: recorded by the project team with time and method.
- **Inference**: interpretation derived from facts or observations.
- **Hypothesis**: testable proposed explanation.
- **Recommendation**: proposed action that is not evidence of an outcome.
- **Insufficient evidence**: not currently supportable.

## Source record

Record Source ID, author/organization, date, title, source type, URL, access date, summary, supported claim, unsupported claim, applicability, limitation, and verification status. Never cite a search-results page when an original source is available.

## Data integrity

- Make raw data append-only.
- Represent missing values consistently as `NA` or another documented token, never zero by default.
- Flag impossible, duplicate, and outlier values; do not delete them automatically.
- Preserve original value, proposed correction, reason, reviewer, and date.
- Distinguish input error from real anomaly.
- Keep a data dictionary and transformation log.

## Publication checklist

- Sources resolve and directly support claims.
- Research/design methods match the described outputs.
- Values, units, dates, sample counts, and group names agree across files.
- Limitations and alternative explanations are visible.
- AI contributions are disclosed when relevant.
- Restricted information and secrets are absent.
- Human reviewer and approval date are recorded.

)

def main() -> int:
    parser = argparse.ArgumentParser(description="Build a read-only artifact manifest CSV.")
    parser.add_argument("project_root", type=Path)
    parser.add_argument("--project-id", required=True)
    parser.add_argument("--output", type=Path, required=True)
    parser.add_argument("--include-restricted", action="store_true")
    parser.add_argument("--dry-run", action="store_true")
    args = parser.parse_args()

    root = args.project_root.resolve()
    output = args.output.resolve()
    if not root.is_dir():
        print("ERROR: project_root must be an existing directory.", file=sys.stderr)
        return 2
    if not PROJECT_RE.fullmatch(args.project_id):
        print("ERROR: Invalid project ID.", file=sys.stderr)
        return 2
    if output.exists() and not args.dry_run:
        print("ERROR: Output already exists; nothing was overwritten.", file=sys.stderr)
        return 3

    warnings = 0
    for file in sorted(path for path in root.rglob("*") if path.is_file()):
        if file.resolve() == output:
            continue
        relative = file.relative_to(root)
        restricted = is_restricted(relative)
        if restricted and not args.include_restricted:
            continue
        match = NAME_RE.fullmatch(file.name)
        warning = ""
        artifact_type = file.suffix.lower().lstrip(".") or "file"
        version = ""
        status = "draft"
        created = ""
        if match:
            if match.group("project") != args.project_id:
                warning = "filename project ID differs from manifest project"
            artifact_type = match.group("artifact")
            version = match.group("version")
            status = match.group("status")
            created = match.group("date")
        else:
            warning = "filename does not match formal artifact pattern"
        if warning:
            warnings += 1
        rows.append(
            {
                "artifact_id": f"{args.project_id}-A{len(rows) + 1:03d}",
                "project_id": args.project_id,
                "name": file.name,
                "artifact_type": artifact_type,
                "version": version,
                "status": status,
                "canonical_location": "local-inventory",
                "path_or_url": relative.as_posix(),
                "privacy": "restricted" if restricted else "internal",
                "created": created,
                "verified_date": "",
                "reviewer": "",
                "source_data": "",
                "checksum": "",
                "naming_warning": warning,
            }
        )

    print(f"Artifacts inventoried: {len(rows)}")
    print(f"Naming warnings: {warnings}")
    if args.dry_run:
        print("DRY RUN: no manifest was written.")
        return 0

    output.parent.mkdir(parents=True, exist_ok=True)
    with output.open("x", encoding="utf-8-sig", newline="") as handle:
        writer = csv.DictWriter(handle, fieldnames=FIELDS)
        writer.writeheader()
        writer.writerows(rows)
    print(f"Manifest written: {output}")
    return 0


if __name__ == "__main__":
    raise SystemExit(main())

def parse_scalar(value: str) -> Any:
    value = value.strip()
    if not value:
        return ""
    if value in {"true", "false"}:
        return value == "true"
    if (value.startswith('"') and value.endswith('"')) or (
        value.startswith("'") and value.endswith("'")
    ):
        return value[1:-1]
    return value


def parse_markdown(path: Path) -> tuple[dict[str, Any], str]:
    text = path.read_text(encoding="utf-8")
    lines = text.splitlines()
    if not lines or lines[0].strip() != "---":
        return {}, text
    data: dict[str, Any] = {}
    for line in lines[1:]:
        if line.strip() == "---":
            break
        if not line.strip() or line.lstrip().startswith("#") or line.startswith((" ", "\t")):
            continue
        if ":" in line:
            key, value = line.split(":", 1)
            data[key.strip()] = parse_scalar(value)
    return data, text


def load(path: Path) -> tuple[dict[str, Any], str]:
    if path.suffix.lower() == ".json":
        text = path.read_text(encoding="utf-8")
        value = json.loads(text)
        if not isinstance(value, dict):
            raise ValueError("JSON root must be an object.")
        return value, text
    return parse_markdown(path)


def main() -> int:
    parser = argparse.ArgumentParser(description="Validate project workflow metadata.")
    parser.add_argument("metadata_file", type=Path)
    parser.add_argument("--json", action="store_true", help="Emit machine-readable output.")
    args = parser.parse_args()

    if not args.metadata_file.is_file():
        print("ERROR: Metadata file does not exist.", file=sys.stderr)
        return 2
    try:
        data, text = load(args.metadata_file)
    except Exception as exc:
        print(f"ERROR: Could not parse metadata: {exc}", file=sys.stderr)
        return 2

    errors: list[str] = []
    warnings: list[str] = []
    for field in sorted(REQUIRED):
        if field not in data or data[field] == "" or data[field] is None:
            errors.append(f"Missing required field: {field}")

    project_id = str(data.get("project_id", ""))
    if project_id and not PROJECT_RE.fullmatch(project_id):
        errors.append("Invalid project_id format or type.")
    if project_id and data.get("project_type"):
        if str(data["project_type"]).upper() != project_id.split("-", 1)[0]:
            errors.append("project_type does not match project_id prefix.")

    slug = str(data.get("slug", ""))
    if slug and not re.fullmatch(r"[a-z0-9]+(?:-[a-z0-9]+)*", slug):
        errors.append("slug must use lowercase ASCII letters, digits, and hyphens.")
    version = str(data.get("version", ""))
    if version and not VERSION_RE.fullmatch(version):
        errors.append("version must look like 1.0 or 1.0.0 without a leading v.")

    for field, allowed in ENUMS.items():
        if field in data and str(data[field]) not in allowed:
            errors.append(f"Invalid {field}: {data[field]}")

    manager = str(data.get("task_manager", ""))
    if manager == "notion" and data.get("linear_authoritative") is True:
        errors.append("Notion and Linear cannot both be authoritative.")
    if manager == "linear" and data.get("notion_authoritative") is True:
        errors.append("Notion and Linear cannot both be authoritative.")
    if "," in manager or "+" in manager:
        errors.append("task_manager must contain only one authoritative system.")

    if str(data.get("privacy", "")) == "public":
        restricted_markers = (
            r"(?im)^\s*(api[_ -]?key|password|token)\s*:\s*\S+",
            r"(?im)^\s*(student[_ -]?name|學生姓名)\s*:\s*\S+",
        )
        if any(re.search(pattern, text) for pattern in restricted_markers):
            warnings.append("Public metadata may contain restricted information; review manually.")

    result = {"errors": errors, "warnings": warnings, "passed": not errors}
    if args.json:
        print(json.dumps(result, ensure_ascii=False, indent=2))
    else:
        for item in errors:
            print(f"ERROR: {item}")
        for item in warnings:
            print(f"WARNING: {item}")
        print("PASS" if not errors else "FAIL")
    return 0 if not errors else 1

    raise SystemExit(main())
