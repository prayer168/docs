1. AI Agent 會自動調用 JavaScript 函式庫嗎？

核心答案：AI Agent「可能」會自行選擇與安裝套件，但不保證正確、必要、相容或適合部署環境。對重要功能，最好明確指定；對尚未確定的功能，先要求 AI 做技術選型，再開始寫程式。

方式 A：完全自動

只描述功能，由 AI 決定原生 JavaScript 或第三方套件。速度快，但容易選錯、重複引用或過度設計。

原型階段

方式 B：明確指定

指定 Three.js、Chart.js、GSAP 等工具及版本。結果穩定，適合關鍵模擬與既有專案。

正式開發

方式 C：先選型後實作

先讓 AI 比較工具、提出理由、風險與替代方案，確認後才安裝與開發。通常是最佳方式。

推薦

AI 真正「調用」套件時，會做哪些事？

在 Codex、Claude Code、Cursor Agent 等可修改專案的工具中，調用通常代表：修改 package.json、執行 npm install、新增 import、建立元件與初始化程式、更新建置設定並執行測試。一般聊天對話只能產生程式碼，並不等於已經在您的電腦安裝套件。

2. 技術選型的八項基本原則

1先定義學習目標
2先用原生能力評估
3一個套件一項責任
4避免功能重疊
5確認手機與觸控
6固定套件版本
7評估維護與授權
8完成後移除未使用套件
不要為了「科技感」而堆疊套件。普通按鈕、表單、分頁、摺疊與簡單拖曳，原生 HTML、CSS、JavaScript 往往已經足夠。套件越多，載入、除錯、版本衝突與資安風險也越高。

只部署在 GitHub Pages 的純前端網站，不能安全保存私密金鑰。Supabase 的匿名金鑰可依 Row Level Security 設計公開使用，但服務角色金鑰、OpenAI API Key 與管理權限金鑰不可放在前端。

11. AI Agent 開發工作流程

  1. 讀取現有專案：確認框架、套件管理器、目錄、部署環境與既有依賴。
  2. 需求拆解：學習目標、使用者、裝置、互動方式、資料與輸出。
  3. 技術選型：先判斷原生能力，再比較必要套件。
  4. 最小原型：只完成一條核心流程，不先做大量裝飾。
  5. 驗證科學正確性：公式、單位、變項、限制與資料來源。
  6. 完成 RWD 與無障礙：觸控、鍵盤、對比、文字大小、減少動畫。
  7. 測試與效能：Playwright、Lighthouse、低階手機與網路限制。
  8. 清理依賴：移除未用套件、固定版本、生成 README。
  9. 正式部署：確認 base path、環境變數與 GitHub Actions。
AI 不應在未說明理由時自行加入多個重型框架，也不應為純前端 GitHub Pages 專案加入無法執行的伺服器端程式。

12. 可直接交給 AI Agent 的完整提示詞

提示詞 A：先選型，再實作

你是一位資深前端架構師、數位教材設計師與自然科教育科技工程師。

請先讀取目前專案的所有重要檔案，確認使用的框架、套件管理器、既有依賴、建置方式與部署環境，再規劃功能。不要直接開始大量寫程式。

專案目標：建立一個適合國小／國中使用的數位互動教材網站。
教材主題：【請填寫】
主要使用者：【請填寫】
核心互動：【請填寫】
部署平台：GitHub Pages
裝置：桌機、平板、手機
語言：繁體中文

請依序執行：
1. 將需求拆成「教學內容、互動、資料、視覺、儲存、部署」六部分。
2. 先判斷哪些功能可用原生 HTML、CSS、JavaScript 完成。
3. 只有確實需要時才選用第三方 JavaScript 函式庫。
4. 對每一個擬採用的套件，列出名稱、用途、選擇理由、替代方案、風險、授權與預估對載入效能的影響。
5. 禁止加入功能重疊的套件，例如同時加入多套動畫函式庫。
6. 若涉及圖表、物理、3D、地圖、遊戲或聲音，請選擇最適合的專用工具。
7. 先提出技術架構、檔案結構、資料流與互動流程，再建立最小可用原型。
8. 完成後執行 lint、測試與正式 build，修正所有錯誤。
9. 驗證 360px 寬度無水平捲軸，滑鼠與觸控都能操作。
10. 不得將 API Key、服務角色金鑰或私密資料寫入前端。
11. 對科學模擬標示模型假設、單位與限制，不可把視覺動畫誤稱為精密科學計算。
12. 最後輸出已使用套件清單、未採用方案、測試結果與部署說明。

提示詞 B：限制 AI 不要濫用套件

請先檢查目前專案，再進行修改。優先使用原生 Web API；除非能明確降低複雜度、提升正確性或提供無法合理自行實作的能力，否則不要新增第三方套件。

新增任何套件前必須：
- 說明用途與不可替代性
- 檢查是否與既有套件功能重疊
- 確認仍在維護、授權可用、支援目前框架
- 評估 bundle 大小與手機效能
- 固定版本並更新 lockfile

完成後移除未使用的 import、套件與測試程式，並執行正式 build。

提示詞 C：針對自然科互動教材

請建立「【教材名稱】」自然科數位互動教材。

技術選型原則：
- 科學動畫與粒子模擬可評估 p5.js。
- 需要剛體重力與碰撞時評估 Matter.js 或 Rapier。
- 需要 3D 模型時使用 Three.js，模型優先採 glTF／GLB，並提供低效能裝置降級方案。
- 一般圖表使用 Chart.js；大型儀表板才考慮 ECharts；高度客製視覺化才使用 D3.js。
- 拖曳普通 HTML 元素使用 Pointer Events 或 Interact.js；多圖層 Canvas 編輯才使用 Konva.js／Fabric.js。
- 動畫使用 GSAP 時，必須支援 prefers-reduced-motion。
- 學習紀錄先使用 LocalStorage；大量離線資料使用 IndexedDB／Dexie。

教材必須包含：學習目標、概念說明、互動模擬、控制變因、觀察紀錄、資料圖表、挑戰任務、結果解釋、模型限制與重設功能。所有數值必須標示單位，手機和平板可操作。

13. 效能、資安、隱私與授權

效能

  • 使用動態 import()，只在需要的頁面載入 Three.js、Plotly.js 等大型套件。
  • 壓縮 GLB、圖片與音訊；限制貼圖尺寸、粒子數、陰影與裝置像素比。
  • 動畫使用 requestAnimationFrame，頁面隱藏時暫停。
  • 大量資料採抽樣、分頁、Web Worker 或虛擬列表。

資安與兒童隱私

  • 前端輸入與後端輸入都要驗證；避免直接插入未過濾 HTML。
  • 建立 Content Security Policy，限制腳本、框架與連線來源。
  • 學生姓名、照片、聲音、位置與作品屬敏感教學資料，應最小化蒐集。
