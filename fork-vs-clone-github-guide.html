Fork 與 Clone 有什麼不同？

用最清楚的方式理解 GitHub 雲端副本、本機下載、開源協作、Pull Request、 origin 與 upstream 的完整關係。

文章目錄

快速理解 核心差異比較 Fork 是什麼 Clone 是什麼 Fork＋Clone 協作流程 origin 與 upstream 什麼時候該用哪一個 常見錯誤 常見問題 重點整理

一、先用一句話快速理解

Fork：複製到自己的 GitHub 在 GitHub 伺服器上，將別人的 Repository 複製成一份屬於自己的遠端版本。
Clone：下載到自己的電腦 將 GitHub 上的 Repository 完整下載到本機，方便使用 VS Code、Codex 或其他工具編輯。
最重要的觀念： Fork 發生在雲端，Clone 發生在本機。兩者不是互相取代，而是經常一起使用。

假設某位老師在 GitHub 上公開了一套自然科數位教材。你想保留自己的修改版本， 可以先 Fork 到自己的帳號；接著要在電腦上實際編輯，就再把自己的 Fork Clone 下來。

二、Fork 與 Clone 核心差異比較

比較項目 Fork Clone
基本意思 在 GitHub 上複製一份 Repository 把 Repository 下載到本機
副本位置 自己的 GitHub 帳號 自己的電腦資料夾
是否建立新 Repository 會，在自己的帳號建立遠端 Repository 不會，只建立本機工作目錄
是否需要 GitHub 帳號 通常需要 公開專案通常不需要登入也能 Clone
主要用途 保留個人副本、修改別人專案、參與開源協作 本機編輯、測試、執行與提交版本
是否影響原專案 不會直接影響原專案 本機修改也不會自動影響遠端
常見後續動作 Clone、Push、建立 Pull Request 建立 Branch、修改、Commit、Push
記憶口訣： Fork 是「雲端複製」，Clone 是「下載到電腦」。

三、Fork 是什麼？

Fork 是 GitHub 提供的伺服器端功能。當你按下某個 Repository 頁面右上方的 Fork，GitHub 會在你的帳號中建立一份副本。

Fork 前後的關係

原始專案：
github.com/original-owner/example-project

Fork 後的個人副本：
github.com/your-name/example-project

GitHub 仍會記錄這份 Repository 是從哪個原始專案 Fork 而來，因此你之後可以：

  • 同步原始專案的新版本。
  • 把自己的修改提交成 Pull Request。
  • 保留一套不影響原作者的個人版本。

適合使用 Fork 的情況

  • 你沒有原專案的寫入權限。
  • 你想修正開源專案的錯誤。
  • 你想新增功能，再提交 Pull Request。
  • 你想保留自己的客製化版本。
  • 你想基於別人的專案發展不同方向。
注意： Fork 不代表專案已經下載到你的電腦。Fork 完成後，通常仍需要再 Clone。

四、Clone 是什麼？

Clone 是 Git 指令，用來把遠端 Repository 完整複製到本機。它不只是下載目前檔案， 還會取得 Git 版本紀錄、Branch 資訊與遠端設定。

基本 Clone 指令

git clone https://github.com/your-name/example-project.git

Clone 完成後，通常會取得：

  • 專案程式碼與圖片等檔案。
  • Git 提交紀錄。
  • 目前可取得的 Branch 資訊。
  • 名為 origin 的遠端 Repository 設定。

Clone 後進入專案資料夾

cd example-project

查看遠端設定

git remote -v
實務觀念： Clone 之後，你在本機修改檔案，不會自動改到 GitHub。 必須經過 Commit 與 Push，變更才會送回遠端。

五、Fork 與 Clone 的標準開源協作流程

當你要修改一個沒有寫入權限的公開專案時，最常見流程如下：

1
Fork 原始專案

把原專案複製到自己的 GitHub 帳號。

2
Clone 自己的 Fork

將自己的遠端副本下載到本機。

3
建立新 Branch

把每次修改放在獨立分支中。

4
修改並測試

編輯程式、文件或教材內容。

5
Commit

把本機修改記錄成一個版本。

6
Push

將 Branch 推送到自己的 Fork。

7
建立 Pull Request

請原作者審查並考慮合併。

完整指令範例

# 1. Clone 自己的 Fork
git clone https://github.com/your-name/example-project.git

# 2. 進入專案
cd example-project

# 3. 建立並切換到新 Branch
git switch -c fix-homepage

# 4. 修改完成後加入暫存區
git add .

# 5. 建立 Commit
git commit -m "修正首頁內容"

# 6. 推送到自己的 GitHub
git push -u origin fix-homepage

推送完成後，再回到 GitHub 建立 Pull Request，將自己的 Branch 與原始專案進行比較。

六、origin 與 upstream 是什麼？

Fork 專案後，為了分清楚「自己的 Fork」與「原作者的 Repository」， 通常會使用兩個遠端名稱。

origin 通常指向你自己的 Fork。平常的 Push 多半送到這裡。
upstream 通常指向原作者的 Repository，用來取得原專案的新更新。

加入 upstream

git remote add upstream https://github.com/original-owner/example-project.git

檢查遠端

git remote -v

可能看到：

origin    https://github.com/your-name/example-project.git
upstream  https://github.com/original-owner/example-project.git

同步原始專案最新內容

git fetch upstream
git switch main
git merge upstream/main
有些專案的預設分支不叫 main，可能叫 master 或其他名稱， 使用前要先確認。

七、什麼時候該用 Fork？什麼時候只要 Clone？

自己的專案

通常直接 Clone，不需要 Fork。

Clone → Branch → 修改 → Push

團隊專案且有權限

通常直接 Clone，再建立 Branch 與 Pull Request。

Clone → Branch → PR

別人的專案且無權限

先 Fork，再 Clone，最後用 Pull Request 貢獻。

Fork → Clone → PR

快速判斷

  • 只是想在本機閱讀、執行或測試：Clone。
  • 想修改自己的專案：Clone。
  • 想修改別人的專案，而且沒有權限：Fork，再 Clone。
  • 想建立個人客製版本：Fork。
  • 已經是團隊協作者：通常不需要 Fork。

八、初學者常見錯誤

錯誤一：以為 Fork 就會下載到電腦

Fork 只會在 GitHub 建立遠端副本。要在本機編輯，仍要執行 Clone。

錯誤二：Clone 別人的專案後，直接 Push

如果你沒有原專案寫入權限，Push 通常會被拒絕。應先 Fork，再 Clone 自己的 Fork。

錯誤三：直接在 main 修改所有內容

建議每次功能或修正都建立獨立 Branch，方便回復、比較與建立 Pull Request。

錯誤四：Fork 後長期不更新

原始專案持續更新時，你的 Fork 可能逐漸落後。應定期從 upstream 同步。

錯誤五：把 origin 當成原作者專案

在 Fork 工作流程中，origin 通常是自己的 Fork；原作者專案通常設為 upstream。

九、常見問題

Fork 會影響原作者的專案嗎？

不會。Fork 是獨立的遠端副本，除非原作者接受你的 Pull Request，否則不會改到原專案。

公開 Repository 可以不 Fork，直接 Clone 嗎？

可以。你可以在本機閱讀、測試與修改；只是沒有權限時，通常不能直接 Push 回原專案。

Fork 後一定要提出 Pull Request 嗎？

不一定。你可以只保留自己的版本，也可以持續發展成不同用途的專案。

Clone 會下載所有 Branch 嗎？

Clone 會取得遠端 Branch 的相關資訊，但本機通常只會自動建立並切換到預設 Branch。

我可以刪除 Fork 嗎？

可以。Fork 本質上仍是一個 Repository，可在 GitHub Repository 設定中刪除。

GitHub Desktop 也能完成 Clone 嗎？

可以。GitHub Desktop、VS Code 與命令列都能執行 Clone，差別只在操作介面。

十、重點整理

Fork：把別人的 Repository 複製到自己的 GitHub 帳號。

Clone：把遠端 Repository 下載到自己的電腦。

origin：通常代表自己的遠端 Repository 或 Fork。

upstream：通常代表原始專案。

無權限參與開源專案：Fork → Clone → Branch → Commit → Push → Pull Request。

只要記住「Fork 在雲端、Clone 在本機」，就能掌握兩者最核心的差異。 在實際 GitHub 協作中，它們常常是同一套工作流程中的不同步驟。
